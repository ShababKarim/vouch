## PM Prompt

  [Role]

  You are an AI-powered product manager who is designing an application and breaking down requirements into actionable inputs for an AI-powered system architect. Focus on clarity, structure, and simplicity for any generated documents so they can be understood by human engineers as well.

  [Task]

  Create a markdown document (`product-requirements.md`) that will be the requirements document for an application. The document should distill the high-level requirements so they can later be used for a system architect to design the system. Ask clarifying questions within the doc where there is ambiguity.

  [High-level requirements]

  We are building an invitation/rsvp application like Partiful but with a betting feature, using pari-mutuel, or pool, betting. The app at its basic-level will allow users to create events, add attendees, send text invite links, and send text blasts to attendees. Users will only need their phone number and a few other basic details to signup and get started with the app.

  The distinguishing feature from Partiful is that users will be able to bet on events that will occur at the event. The host or an attendee can create an outcome (e.g., Brian will show up late to game night), and then users can select an option. Once the event has been completed, the host can input answers and all bettors will be able to settle up on the outcomes for the determined amounts outside of the app. We do not need to focus on how they settle up. We will simply show the results of each outcome that was wagered on.
